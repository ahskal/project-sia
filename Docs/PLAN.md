# Sia 구현·방향 계획

## 목표

중세 판타지 3인칭 액션 RPG의 **싱글플레이 수직 슬라이스**를 먼저 완성한다. 플레이어가 지역을 탐색하고, 아이템을 얻고, 전투와 상호작용 목표를 해결해 한 번의 플레이를 마칠 수 있는 상태가 1차 목표다. 멀티플레이는 싱글플레이 핵심 루프가 검증된 뒤 진행한다.

- 기준: `PRD.md`, 현재 UE 5.8 프로젝트
- 구현: 게임플레이 로직은 C++17, 데이터·UI·애니메이션 연결은 에셋과 블루프린트 활용
- 완료 판단: 각 단계의 완료 조건을 실제 플레이와 자동화 검증으로 확인

## 현재 구현 상태

- **기반 있음:** 캐릭터 이동·점프·대시, 카메라, 공격 판정·피해·체력, HUD
- **대부분 구현:** 아이템 데이터 테이블, 인벤토리 스택·무게·장비 슬롯·퀵슬롯, 픽업·소비·버리기, 인벤토리 UI
- **보완 필요:** 장착 무기 메시/소켓 연결과 공격력 반영, 방어구 능력치의 피해 반영, 공격 몽타주·노티파이 연결과 피격/사망 애니메이션
- **아직 구현 근거 없음:** 자원 채집 노드, 레벨·스탯 성장, 몬스터 AI, NPC 대화·퀘스트, 멀티플레이 복제
- `Source/Sia/Tests/InventoryTests.cpp`에 인벤토리 자동화 테스트가 있다. 이번 계획 작성 중 빌드·테스트는 실행하지 않았다.

## 구현 순서

### Level 0 — 첫 플레이 범위 확정

**상태:** 계획 필요. PRD에 장르와 시스템은 있으나 스토리와 첫 플레이 목표는 미정.

- 한 줄짜리 플레이 목표와 핵심 반복 구조를 정한다: 탐색 → 전투/수집 → 보상·성장 → 목표 완료.
- 첫 수직 슬라이스의 지역, 적, 상호작용 목표를 최소 규모로 정한다.
- 성장 스탯, 장비 효과, 퀘스트 완료 조건을 구현 가능한 규칙으로 적는다.

**완료 조건:** 첫 플레이의 시작·성공 조건과 포함할 시스템이 문서에 명시되고, 이후 단계의 완료 조건을 판단할 수 있다.

### Level 1 — 조작·전투 프로토타입

**상태:** 부분 구현. 이동·대시·공격 판정과 피해 기반이 있다.

- 공격 입력에서 애니메이션 몽타주를 재생하고, 공격 구간에만 히트박스를 켜고 끈다.
- 피격·사망 처리를 연결해 체력 0 이후 입력과 공격이 일어나지 않게 한다.
- 테스트용 적 또는 전투 대상을 두고 공격력, 넉백, 체력 UI를 한 흐름으로 확인한다.

**완료 조건:** 플레이어가 이동·회피·공격해 대상을 처치할 수 있고, 한 공격의 피해가 의도한 횟수만 적용되며 피격과 사망이 화면에 표현된다.

### Level 2 — 장비·아이템·채집 루프

**상태:** 인벤토리 기반은 있음. 장비 효과와 채집은 미구현.

- 인벤토리 시스템을 재사용한다. 새 인벤토리를 만들지 않는다.
- 무기를 장착하면 메시가 소켓에 표시되고 무기 데이터가 공격력에 반영되게 한다.
- 방어구 수치가 받는 피해에 반영되게 한다.
- 상호작용 가능한 자원 노드와 채집 결과를 추가하고, 획득량·도구 조건을 데이터로 조정할 수 있게 한다.
- 인벤토리 용량이 부족하면 획득 실패 또는 부분 획득을 명확히 보여준다.

**완료 조건:** 무기·방어구 장착 전후의 전투 수치 차이가 확인되고, 자원 노드에서 얻은 아이템이 기존 인벤토리에 들어가며 한도 초과 아이템이 사라지지 않는다.

### Level 3 — 몬스터·NPC·퀘스트

**상태:** 미구현.

1. 몬스터의 대기·추적·공격·피격·사망 상태를 구현한다.
2. 처치 보상과 아이템 드랍 확률을 데이터로 설정한다.
3. NPC 대화 상호작용과 단일 목표 퀘스트를 구현한다.
4. 퀘스트 완료와 보상을 UI로 알린다.

**완료 조건:** 몬스터 처치와 NPC 목표 수행이 각각 성공·실패 상태를 갖고, 보상과 퀘스트 진행도가 일관되게 갱신된다.

### Level 4 — 성장·첫 플레이 수직 슬라이스

**상태:** 미구현.

- 전투·퀘스트 보상에서 경험치를 얻고 레벨업하도록 한다.
- Level 0에서 정한 스탯 성장 규칙을 적용하고 HUD/상태 UI에서 확인할 수 있게 한다.
- 작은 플레이 공간에 조작, 아이템 획득, 전투, 퀘스트 목표, 완료 지점을 연결한다.
- 플레이 흐름을 처음부터 끝까지 반복 확인하고 막힘과 보상 누락을 수정한다.

**완료 조건:** 새 게임 시작부터 목표 완료까지 한 번의 플레이가 가능하고, 전투·퀘스트 보상과 성장 결과를 확인할 수 있다.

### Level 99 — 멀티플레이

**상태:** 후순위. 현재 확인한 게임플레이 코드에는 네트워크 복제가 없다.

- 싱글플레이 수직 슬라이스가 안정된 뒤 별도 네트워크 프로토타입으로 착수한다.
- 이동, 공격·피해, 인벤토리·아이템 획득, 퀘스트 진행의 서버 권한과 복제 범위를 정한다.
- 네트워크 적용 전에도 핵심 상태의 소유 주체와 변경 경로를 점검해 이후 재작업을 줄인다.

**완료 조건:** 두 클라이언트가 같은 전투·아이템·퀘스트 결과를 관찰하고, 중복 획득이나 클라이언트 단독 상태 변경이 발생하지 않는다.

## 단계별 검증 기준

- C++ 변경마다 UE 5.8 Development Editor 빌드를 통과시킨다.
- 인벤토리 변경은 기존 `Sia.Inventory` 자동화 테스트를 실행하고, 새 규칙에 맞는 테스트를 추가한다.
- 전투·채집·퀘스트는 핵심 성공 경로와 실패 경로를 자동화 또는 PIE 플레이로 확인한다.
- 단계 종료 시 완료 조건, 실행한 검증, 미확인 항목을 기록한다.

## 우선순위 요약

1. **Level 0:** 첫 플레이 목표 확정
2. **Level 1:** 공격 애니메이션과 전투 완성
3. **Level 2:** 이미 있는 인벤토리에 장비 효과와 채집 연결
4. **Level 3:** 몬스터 보상과 NPC 퀘스트
5. **Level 4:** 레벨·스탯 성장과 수직 슬라이스 완성
6. **Level 99:** 멀티플레이
